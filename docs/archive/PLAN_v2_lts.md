## 一、子代理使用统计与失败分析

### 1.1 累计用量

| 指标 | 数值 |
|------|------|
| 累计派发子代理 | **38** 次 |
| 成功产出报告 | **21** 份（docs/review_b1~b4 共 12 份 + api_report_* 3 份 + api_verified 1 份 + 零散 5 份） |
| 失败 / 被取消 | **17** 次 |
| 成功率 | **≈55%** |

### 1.2 失败原因分类

| 类别 | 次数 | 典型表现 | 根因 |
|------|------|---------|------|
| **模型服务 503** | 9 | `Transient error: [503] all accounts are temporarily unavailable` | 子代理模型后端瞬时过载；与任务内容无关 |
| **DNS 解析失败** | 4 | `Unable to resolve host "server.344977.xyz"` | `/etc/resolv.conf` 被容器改回 `192.168.0.1`，子代理的模型调用域名解析不了 |
| **超时（40/45 分钟上限）** | 3 | `termination_reason=timeout` | 任务书要求「完整读 30+ 文件 + 逐个 curl 实测」，40 分钟根本读不完 |
| **连接重置** | 1 | `Connection reset` | 长时间网络请求后 socket 被断 |
| **任务书缺陷** | 3 | 代理去装 SDK / 跑偏 | 任务书未写死「禁止下载 SDK / 禁止装包 / 禁止 clone」 |
| **落盘缺失** | 2 | 读完文件但没写报告就超时 | 任务书要求「最后统一写报告」→ 超时即全部丢失 |

### 1.3 教训（已固化为规范）

| # | 教训 | 落地规则 |
|---|------|---------|
| L1 | 子代理是**易失资源**，不能是唯一产出通道 | 关键路径的修复与验证由主代理亲自做 |
| L2 | 报告必须**实时落盘**，不能最后统一写 | 任务书强制：每读完一个模块立刻 append 到 `docs/xxx.md` |
| L3 | 超时值必须按**文件量**给足 | 审查类 120 分钟；修复类 60 分钟；禁止 15/25/40/45 |
| L4 | 任务书必须写死**禁止清单** | 「禁止下载 SDK / 禁止装包 / 禁止 clone / 禁止构建 / 禁止改文件」逐条列出 |
| L5 | DNS 是隐性单点故障 | 每次批量派代理前先确认 `resolv.conf` 是 `223.5.5.5` / `114.114.114.114` |
| L6 | 代理产出必须**可验证** | 报告里的每条结论必须带 `文件:行号`，主代理复核后才采信 |

## 四、质量准则（贯穿全程）

1. **每个修复必须对应一个可复现的失败现象**（真机日志 / curl 实测 / 单元测试），不接受"看起来更合理"的改动。
2. **每个端点必须三态实测**（匿名 / 非VIP / VIP），失败样本同样归档。
3. **签名类改动必须与 Node 逐字节比对**（`md5(salt + sorted(k=v) + body + salt)`）。
4. **不做无验证的改动**。改完必须有一处可观测的行为差异。
5. **宁可不发，也不发带暗病的包**。LTS 的定义是"下一个大版本前不用动它"。
6. **一次 push 到底**：中途不 push，CI 只做最终验证。

## 五、风险与预案

| 风险 | 影响 | 预案 |
|------|------|------|
| 上游接口再次变更（今日已见 `special_recommend` 200101） | 部分页面空白 | 直连失败自动回退 kapi；每次发版前重测 `docs/api_verified.md` |
| 滑块/人机验证仍需人工 | 首次登录摩擦 | 已支持 issue#206 全类型；KG 自研滑块可自动 |
| API 中转 `kapi.344977.xyz` 不可用 | 8 个写操作 + top/playlist 受影响 | 直连已覆盖 50 个端点，仅少数回退；写操作需登录态 |
| 签名密钥轮换 | 全量直连失效 | 密钥在 `KgCrypto` 常量，可一处更新；Node 侧同步 |
