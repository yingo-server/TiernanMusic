## 3. 实锤问题清单（26 条）

### A-00【P0｜`TiernanAudioHandler` 从未注册到系统媒体会话：通知栏/锁屏/蓝牙控制的全部状态与 App 内状态不同源，控制指令永不到达 App 队列】
- 代码事实：全仓 `rg 'AudioService.init|JustAudioBackground|TiernanAudioHandler'` 仅有：`audio_service_bootstrap.dart:64` 调 `JustAudioBackground.init(...)`；`player_provider.dart:31-32` `Provider((ref) => TiernanAudioHandler(...))` 直接 `new` 出一个 Handler；**没有任何** `AudioService.init(builder: () => TiernanAudioHandler(...))`。而 `just_audio_background 0.0.1-beta.13` 官方源码 `jab.dart:97-98` 为 `AudioService.init(builder: () => SwitchAudioHandler(BaseAudioHandler()), ...)`，:170 `_audioHandler.inner = _playerAudioHandler`，:374 `class _PlayerAudioHandler extends BaseAudioHandler with QueueHandler, SeekHandler`，:790 由它 `_broadcastState()` 投射 controls/processingState/queueIndex，`audio_service.dart:994-1013` 的 `AudioService.init` 用 `assert(_cacheManager == null)` + 全局 `static late AudioHandler _handler`（:956）保证**进程内只有一个注册 Handler**。
- 因此：`audio_handler.dart:216-245` 的 `playbackState.add(...)`、:258 的 `mediaItem.add(...)`、:280 的 `queue.add(...)`、以及 :637 `skipToNext`/:660 `skipToPrevious`/:629 `seek`/:686 `setShuffleMode`/:694 `setRepeatMode`/:716 `onNotificationDeleted` 都只是这个**未注册对象**的方法；系统侧的 `skipToQueueItem` 由 `jab.dart:644` 的 `seek(SeekRequest(index: index))` 处理、`onNotificationDeleted` 由 `audio_service.dart:2598-2600` 的 isolate 回调经 `IsolatedAudioHandler → SwitchAudioHandler → CompositeAudioHandler.onNotificationDeleted`(`audio_service.dart:2290`) 委派给 JAB 的 `_PlayerAudioHandler`；JAB 未 override，落到 `BaseAudioHandler.onNotificationDeleted()`(`audio_service.dart:3181-3183`：`await stop()` → JAB `stop()` :728)，**不会**调到 `TiernanAudioHandler`。
- 更实锤的可见断层：`jab.dart:596-599` `_updateQueue()` 断言 `sequence.every((source) => source.tag is MediaItem)` 并把 `source.tag as MediaItem` 填进系统队列；本项目 `ah:409-413/439/461` 传的 tag 是 `mediaItem.value`（未注册 Handler 的 `MediaItem?`，_emitMediaItem 已发过 → 非 null，类型正确），但每次 `_applySource` 只 `setAudioSource(AudioSource.uri(...))` **单个 source**，故系统队列长度恒为 1，`currentIndex` 恒为 0，`jab.dart:790` 投射的 `queueIndex` 恒 0；App 内 `playbackState.queueIndex` 却是 `_index`（ah:239，可为 0..N-1）。通知栏「下一首」走 JAB 的 `_PlayerAudioHandler.skipToNext`（`jab.dart:651`），因单曲 `hasNext == false`（`_getRelativeIndex` 无下一项）而**静默无效**；只有 `LoopMode.all` 时引擎可能回绕同一首。
- 违反：第 5 条（同一事实多处权威存储且多处修改，此处是两套媒体会话）、第 3 条（契约先行：`BaseAudioHandler` 的能力契约要求经 `AudioService.init` 注册才生效，代码未满足）、第 4 条（分层单向：data 层 Handler 自行广播 UI/平台状态却无人订阅）、第 9 条（失败/降级必须可观测：静默的双轨无任何日志或诊断）、第 2 条（隐藏依赖：系统媒体会话由第三方插件隐式接管，App 层无从替换/测试）、PLAN §一「通知栏控制与 UI 状态不同步」与 §二「audio_handler 只做 just_audio 适配器（平台通道 ↔ 状态机事件），QueueHandler mixin 弃用」的现状根因。

## 5. 状态机事件表建议（供重写定案）

### 5.1 单一 sealed state + 唯一权威队列
```dart
sealed class PlayerState { const PlayerState(); }
final class PlayerIdle extends PlayerState { const PlayerIdle(); }
final class PlayerLoading extends PlayerState {
  const PlayerLoading(this.song, this.phase, {required this.startedAt, required this.generation});
  final Song song; final NetworkPhase phase; // resolving/detecting/streaming
  final DateTime startedAt; final int generation;
}
final class PlayerPlaying extends PlayerState {
  const PlayerPlaying(this.song, {required this.isPreview, required this.quality, required this.sourceId});
  final Song song; final bool isPreview; final AudioQuality quality; final String sourceId;
}
final class PlayerPaused extends PlayerState {
  const PlayerPaused(this.song, this.reason); // user / system / verification
  final Song song; final PauseReason reason;
}
final class PlayerSuspended extends PlayerState {
  const PlayerSuspended(this.songHash, this.api, this.generation); // 20028 一等公民
  final String songHash; final ApiException api; final int generation;
}
final class PlayerFailure extends PlayerState {
  const PlayerFailure(this.reason, {required this.whatHappened, required this.nextAction, this.retry});
  final FailureReason reason; // engineNotReady/resolveFailed/sourceFailed/queueEmpty/invalidIndex
  final String whatHappened; final String nextAction; final RetryAction? retry;
}
```
- 唯一权威：`PlayerStateMachine._state` + `QueueState{items: List<QueueItem>, index: int, shuffle: bool, repeat: RepeatMode, shuffleHistory: Set<String>}` + `generation`；`_songs[` 只允许出现在状态机文件（PLAN §三.1）。
- **先解决 A-00 再谈状态机**：`audio_handler` 要么按 PLAN 降级为纯 just_audio 适配器并由 `AudioService.init(builder: ...)` 注册同一个 Handler（弃用 `just_audio_background` 的双 Handler），要么彻底放弃 `BaseAudioHandler`/`QueueHandler`/`SeekHandler`，改由 `just_audio_background` 的 `AudioSource` 序列 + `MediaItem` tag 承载系统队列，App 侧只订阅 `AudioService` 的回调事件。二者必须二选一，禁止继续「App 广播一份、插件广播一份」。
- 所有派生事实（mediaItem/queue/playbackState/currentSong/preview/quality/error/engineReady/最近播放）由**一个** reducer 从 `PlayerState` 单向投射，禁止 7 个自建 StreamController。

### 5.3 落地约束（对应 PLAN §三）
1. `_songs/_index/_loading/_playToken/_pendingIndex/_pendingSongHash/_failureStreak/_isPreview/_last*` 全部收进 `PlayerStateMachine` 单文件；`audio_handler` 只保留 just_audio ↔ 事件转换。

3. UI 只 `watch(playerStateProvider)`；mini_player / full_player_page / queue_sheet 共用一张 `PlayerState → Widget` 映射表，`loading/buffering/error/empty/suspended` 互斥（A-16）。
4. 每个异步边界（网络、`setAudioSource`、`play()`、`seek`、`completed`、验证）携带 `generation + sourceId` 并在回调入口校验；finally 只由该 generation 持有者关闸（第 18/19 条）。
