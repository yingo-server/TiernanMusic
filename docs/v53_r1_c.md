## 最终判定（回答任务书的四个「判定」问题）

1. **四重检测五级回退的状态是否真透出 UI**：**否**。服务层有 `probeLog`，但只记录到生效级为止、缺未执行级与逐项 ✓/✗；UI 层把它拼进一个 `isThreeLine: true` 的 ListTile subtitle（被裁剪），硬编码中文，无 loading/错误三态，无逐级结构，无一键重新探测。诊断链在「状态→UI」这一跳断裂（C-03/C-08/C-18/C-20/C-65）。
2. **授权返回是否重探测**：**路径维度是、权限态与启动期否**。设置页 `didChangeAppLifecycleState(resumed)` 重建 3 个 Future 会真跑 `resolveRoot()`（如实记录）；但服务层 `requestAllFilesAccess()` 返回后不清缓存/不触发探测，权限态用恒真的 `hasStorageWriteAccess()` 刷新，`bootstrapServices()` 启动期零探测（C-10/C-22/C-24/C-32）。
3. **probeLog 可见性**：**技术存在、实际不可读**。`StorageResolution.probeLogText` 有定义，但展示在一个三行 ListTile 里、与 path/mode/lastProbeError 拼成一大段 Text，且 `lastProbeError` 是静态全局会被其它权限请求覆写（C-04/C-08/C-18/C-20）。
4. **播放页信息层级 / 按钮语义 / 长文案 / 三态**：四项全部不合格——层级挤在同一 Row（C-36）、收藏与队列双入口且 40dp（C-37/C-42）、歌词不在入口行（C-38）、无 loading 态与错误态（C-33/C-34）、引擎与歌词文案硬编码中文（C-35/C-39）、arb 中 7 个键 11 语最长 ≥70 字且错误态无具体下一步（C-58/C-59）；法语 `notPlaying` 语义反转（C-55）。
