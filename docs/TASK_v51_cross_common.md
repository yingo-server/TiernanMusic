## 交叉机制（与以往批次不同）
- **同一批三个代理检查完全相同的文件范围**，但视角不同：
  - 视角 A：**功能正确性**（链路闭环、参数/返回契约、状态机、单位、字段形态）
  - 视角 B：**鲁棒与代码质量**（异常、边界、并发、资源对称、缓存维度、第 1/6/9/11/14/18/19/20/21/23/25/28/29 条）
  - 视角 C：**用户路径与一致性**（真机可见后果、三态、i18n、生命周期、跨模块契约、回归）
- 三份报告由主代理合并为 `docs/v51_cross_b<N>_merged.md`：标注「三视角共识 / 双视角 / 单视角」、矛盾项由主代理读代码裁决、误报标注原因。
- 禁止读 `docs/v51_cross_b*_merged.md` 与其它批报告（防锚定）；可以读本批任务书指定的业务代码。

## ⚠️ 硬性规则（违反任一 = 任务失败）
1. **只读**：禁止修改任何代码文件；唯一可写的是自己的报告文件。
2. **完整阅读**：范围内每个 .dart 文件必须 `file_read` 从头读到尾；**禁止 grep/正则筛源码**（只能用于统计/核对 import 路径有效性）。
3. **实时落盘**：每读完一个文件立刻 append 到报告，不允许最后统一写。
4. **只报问题，不给修复建议、不给代码片段**；每条必须含：
   ```
   ### <文件>:<行号> 简述
   - 级别：P0/P1/P2/P3（P0=崩溃/数据损坏/重复提交，P1=核心功能失效/静默错误，P2=次要/边界/性能，P3=整洁度）
   - 违反：QUALITY_STANDARD 第 N 条
   - 依据：<代码事实，不推测>
   - 影响：<用户可见后果>
   - 证据等级：实锤 / 静态推演 / 未实测（如实标注）
   ```
5. **绝对禁止**：装 Flutter SDK / 下载 SDK / dart pub get / flutter 命令 / git clone / 构建 / 编译 / 跑测试 / 启动本地服务。允许 `export PATH=$PATH:/opt/dart/bin && dart analyze <file>` 作静态语法检查；Flutter/三方包符号缺失是预期噪音，项目自有类报错才是真错误。
6. **pubspec.yaml / AndroidManifest.xml / Kotlin / CI yml 一行不许动**。
7. 禁止读 `docs/batch*`、`docs/v3*review*`、`docs/v4*review*`、`docs/v37*` 等历史审查报告。
8. 报告末尾追加「问题清单（按级别排序）」与「复核通过项（本范围确认到位的设计）」。
9. 收尾前对范围内每个文件跑 `dart analyze` 并**逐文件贴结果**（过滤噪音后，项目自有类 0 错误为通过）；缺一文件即任务失败。
